# fieldstudy｜桌球發球研究工作台

這是一個從 VS Code 啟動的本機前後端專案，包含上傳訓練、落點預測、目標格反推、多球路推薦與 300 組補測資料產生。

## 安裝與啟動

建議使用 Python 3.12。解壓縮後，以 VS Code 開啟 `fieldstudy` 資料夾，在 PowerShell 依序執行：

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m uvicorn app:app --host 127.0.0.1 --port 8000
```

接著開啟 [http://127.0.0.1:8000](http://127.0.0.1:8000)。請透過此網址使用網頁，不要直接開啟 `index.html`。結束時在終端機按 `Ctrl + C`。訓練或搜尋期間不要加 `--reload` 或開多個 worker，背景工作與推薦歷史保存在單一服務程序中。

macOS、Linux：

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m uvicorn app:app --host 127.0.0.1 --port 8000
```

更新舊專案時，請先備份自己的 `data/`、`models/`、`outputs/`，再替換程式並重新安裝套件。本壓縮檔未包含實測資料或已訓練模型。

## 五個功能頁面

| 頁面 | 使用方式 |
|---|---|
| 上傳與訓練 | 拖放或點擊選取多個 Excel。可選擇只使用這次上傳的資料；訓練完成後自動載入新模型。 |
| 四參數預測落點 | 輸入四個機器設定，查看預測落點及前十個類別的機率。 |
| 目標落點反推 | 一次選一格與顯示組數，一起搜尋四參數的完整空間。 |
| 多球路推薦 | 選共同目標格、球路偏好與每種方案數；只在符合固定落點條件的候選中排序。 |
| 推薦補測資料 | 選擇是否產生 300 組，直接使用目前模型的實測訓練資料，預覽並下載；不用再上傳。 |

介面採淺灰背景、白色卡片及藍色選取狀態，沒有 emoji。同列左右卡片的上下邊緣對齊。目標選格固定以 `(1,1)` 為左上角、`(5,5)` 為右下角；X 從上向下遞增，Y 從左向右遞增；第一排依序為 `(1,1)`、`(1,2)`、`(1,3)`、`(1,4)`、`(1,5)`，`(4,3)` 位於第 4 排、第 3 欄，既有落點標籤的意義與資料不做轉換。桌機側欄會在小螢幕改成上方功能列；結果表格在自己的區域內橫向捲動。

## 推薦的固定規則

反推與多球路推薦皆強制採用以下條件，前端不提供調整欄位，API 也不接受降低門檻：

- 模型預測指定目標格的機率至少為 `1.0`。
- 模型預測無效球總機率必須為 `0.0`。
- 所有非目標類別的機率也必須為 `0.0`。
- 不使用四捨五入、近似相等或低機率備用方案。

`0.999999999999` 仍不合格；極小但非零的無效機率仍不合格。若沒有方案就顯示空結果，不會為了湊數放寬條件。若模型從未學到所選類別，會提示需要補充該格資料。

**這裡的 100% 是模型的輸出，不能保證實機每球必中。** 目前標籤是 5×5 的格子，目標指的是指定格，並非格內的精確座標。模型機率也不等同已經過實測校準的命中率。多格機率不能合併當成單一格的 100%，所以每次僅能選一格。

四參數搜尋範圍為 `28 × 9 × 59 × 99 = 1,471,932` 組。每一維都一起搜尋，不固定其中任何一項。搜尋會分批預測並回報進度；500 棵樹掃描完整空間的時間取決於電腦效能，請等候進度完成。

## 多球路選項與每次變化

共有 18 個選項：

| 類型 | 選項 |
|---|---|
| 強度偏好 | 高速球、中速球、低速球 |
| 仰角偏好 | 高仰角、中仰角、低仰角 |
| 左右設定偏好 | 左右設定值偏小、居中、偏大 |
| 旋球設定偏好 | 旋球設定值偏小、居中、偏大 |
| 組合偏好 | 高速＋高仰角、高速＋低仰角、低速＋高仰角、低速＋低仰角 |
| 綜合方案 | 均衡方案、多樣化方案 |

「高速／低速」以出球強度設定排序，不代表已量測球速；仰角與左右也是設定偏好。「均衡」偏好四個設定靠近設備範圍中間；「多樣化」不偏好特定設定大小。旋球值尚無旋轉方向的實測對照，所以不直接命名為上旋、下旋或側旋。

搜尋先篩掉所有不符合落點條件的組合，再按偏好排序。相同目標與相同球路會優先挑選這次服務中尚未顯示的參數，同分時隨機排序，再挑選四維參數有差異的方案。候選不足時提供實際數量；未顯示的候選用完後可以重複，並在結果說明中標示。不同球路可能選到相同組合。重新啟動服務或重新訓練後，跨次顯示紀錄會重置。

## 實測資料格式

Excel 工作表名稱不限，欄位名稱必須完全對應：

| 欄位 | 內容 |
|---|---|
| 測試編號 | 原始實測編號 |
| 仰角角度 | 整數 1–28 |
| 左右位置 | 整數 1–9 |
| 旋球角度 | 整數 1–59；沿用原欄名，實際為機器設定值 |
| 出球強度 | 整數 1–99 |
| 發球1_落點、發球2_落點、發球3_落點、發球4_落點、發球5_落點 | 每組五次實測結果 |

有效落點為 `(1,1)` 至 `(5,5)`；全形括號、逗號與空白會整理成統一格式。

無效結果為 `飛出台面`、`未過網`、`碰桌後彈出`、`球碰網後沒有進入有效區`。`其他無效` 與 `碰桌後彈出` 視為同一類，內部沿用既有模型的 `碰桌後彈出` 標籤，總類別數仍為 29。

訓練允許落點留白，空白的球不參與訓練；有文字但無法辨識的落點會報錯。補測直接使用實際參與目前模型訓練的紀錄，不會把原本空白的球補成假落點。

## 300 組推薦補測

先在「上傳與訓練」完成模型訓練，再到「推薦補測資料」選擇是否產生。此頁不提供上傳欄位，直接使用目前模型的訓練紀錄。畫面會顯示模型名稱、訓練來源檔案、實測設定組數與球數。

新模型保存訓練資料快照，所以重新啟動或移動原始 Excel 後仍可產生補測；不會因後來的檔案內容變動而改用其他資料。補測會排除模型訓練資料的所有四參數組合，包括上傳表中尚無有效落點的設定，並排除本次推薦內的重複組合。

更新前的舊模型若沒有快照，會嘗試讀取 `data/` 中保留的原訓練 Excel，核對參數集合、有效訓練球數及落點類別後重建資料。請保留這些原始訓練檔；若遺失或核對不符，須回到上傳與訓練頁重新訓練。舊模型的核對依既有摘要，並非原始檔的內容雜湊驗證；重新訓練後會改用隨模型保存的固定快照。

1. 將四參數依設備上下限 Min–Max 縮放至 `[0,1]`。
2. 彙整同參數所有實際訓練球，建立落點分布。
3. 找出正規化歐氏距離 `≤ 0.15`、但分布不同的實測點對，於中點附近產生整數候選。
4. 挑選最多 120 組邊界補強；不足的名額轉給空間探索。
5. 空間探索原訂 150 組，從全域均勻候選池挑選距實測與已選點較遠的組合。
6. 保留 30 組全域隨機驗證；全程排除已有及本次已選參數。

這是依既有實測資料提出的補測區域，不是已確認的物理分類邊界。空間探索使用最多 40,000 組均勻隨機候選池與逐次最遠點挑選。若未測空間不足 300 組，會停止並回報剩餘數量。

CSV 保留原始十個欄位，五球落點留白。Excel 包含 `推薦補測300組`、`採樣策略`、`摘要` 三個工作表。預覽每頁 30 組，可逐頁查看全部 300 組。產生補測不會重新訓練或更改目前模型。

尚未完成訓練或找不到對應實測紀錄時，不會產生補測表。本壓縮檔沒有預先附上假設資料的補測表。

## 模型訓練設定

維持原專案設定：Random Forest 與 Extra Trees 各 500 棵樹，使用 `StratifiedGroupKFold(n_splits=5)` 比較平均 Macro F1，獲勝演算法以全部可用資料重新訓練。

分組依據為四參數組合；同參數的五球與不同測試編號下的重複設定都留在同一 Fold，避免資料洩漏。參數組合不足五組會停止。類別組數不足五組時會提示分層限制。

`models/table_tennis_ball_landing_model.pkl` 儲存正式模型，`outputs/` 儲存每折成績、平均成績、參數重要程度與類別分布。資料只在本機運算。新模型會一併保存實際參與訓練的落點紀錄及來源檔名，供後續補測使用。

不使用網頁也能訓練：將 Excel 放進 `data/` 後執行：

```powershell
.venv\Scripts\python.exe train_model.py
```

## API

| 方法 | 路由 | 用途 |
|---|---|---|
| GET | `/api/model-info` | 模型、球路選項與進行中的工作 |
| POST | `/api/upload-train` | multipart：`files`、`replace_old` |
| POST | `/api/predict` | JSON：`elevation`、`horizontal`、`spin`、`power` |
| POST | `/api/reverse-search` | JSON：`targets`（單元素）、`top_n`（1–100） |
| POST | `/api/multi-route` | JSON：`targets`、`routes`、`n_solutions`（1–20） |
| POST | `/api/sampling` | JSON：`generate`（true／false）；資料來源固定為目前模型訓練資料 |
| GET | `/api/job/{job_id}` | 查詢進度與結果 |
| GET | `/api/sampling/{job_id}/download/{extension}` | 補測下載，extension 為 `csv` 或 `xlsx` |

背景操作回傳 `job_id`，前端每秒查詢工作狀態。一次僅允許一個訓練、搜尋或補測工作。重新整理頁面後會嘗試恢復最近工作；關閉後端會中斷工作，下載檔案仍留在 `outputs/`，但舊的工作下載路由不會跨重啟保留。

## 測試

```powershell
.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.venv\Scripts\python.exe -m pytest tests -q
```

測試包括固定門檻無法降低、極小非零機率拒絕、空結果無備用候選、四維組合掃描、多次方案變化、300 組合法且不重複、邊界不足轉探索、訓練資料來源核對、快照保存與 CSV／Excel 下載串接。合成資料僅用於測試程式，不代表真實球機效能。

## Windows 暫存檔清理修正

若舊版在上傳檢查時出現 `PermissionError: [WinError 32]`，且路徑包含 `Temp\fieldstudy-check-...`，原因是讀取工作表清單的 Excel 工作簿沒有明確關閉。本版在訓練與補測匯入時使用 `with pd.ExcelFile(...)`，並直接透過同一個工作簿讀取工作表，確保成功、略過工作表或發生錯誤時都會釋放檔案。

更新方式：先在後端終端機按 `Ctrl + C`，將新版 `core/data_loader.py`、`core/sampling.py` 覆蓋到原專案，再用原本指令重新啟動。這次不需新增套件，也不需刪除 `data/`、`models/` 或 `outputs/`。

`tests/test_excel_resources.py` 會檢查正常讀取、多工作表、缺欄位、讀取錯誤、參數錯誤與不完整補測資料的檔案關閉情形，並模擬 Windows 對開啟檔案禁止刪除的行為。此模擬不等同於已在 Windows／Python 3.14 實機執行。
